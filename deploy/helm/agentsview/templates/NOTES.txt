Open it:

{{- else if contains "kata" .Values.runtimeClassName }}
  The pod runs under Kata, where kubectl port-forward cannot reach it: the
  server listens inside the VM, not in the pod's network namespace on the node.
  Enable the Ingress, or reach the Service from inside the cluster:
  kubectl --namespace {{ .Release.Namespace }} run agentsview-curl --rm -it --restart=Never --image=curlimages/curl:8.11.1 -- curl -sS http://{{ include "agentsview.fullname" . }}:{{ .Values.service.port }}{{ .Values.server.basePath }}/
{{- else }}
  kubectl --namespace {{ .Release.Namespace }} port-forward svc/{{ include "agentsview.fullname" . }} {{ .Values.service.port }}
  then http://127.0.0.1:{{ .Values.service.port }}{{ .Values.server.basePath }}/
{{- end }}
{{- if .Values.auth.required }}

The browser asks once for the bearer token from Secret {{ .Values.auth.existingSecret }}:
  kubectl --namespace {{ .Release.Namespace }} get secret {{ .Values.auth.existingSecret }} -o jsonpath='{.data.{{ .Values.auth.tokenKey }}}' | base64 -d
{{- else }}

Authentication is off. Only expose this Service through a proxy that
authenticates every request, and keep the pod unreachable from elsewhere.
{{- end }}
